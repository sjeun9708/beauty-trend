# 연령별 뷰티 검색 트렌드 분석 AI

매일 네이버 쇼핑인사이트의 **화장품/미용** 인기검색어를 연령대(10대~60대 이상)별로 1~50위까지 수집하고,
순위 변동을 계산한 뒤, 최근 뉴스·블로그를 근거로 Claude가 "왜 떴는지"를 분석해 HTML 리포트로 만듭니다.

## 동작 순서

1. **수집** (`collector.py`): 기준일과 전일의 연령별 1~50위
2. **변동 분류** (`trends.py`): 신규 진입 / 급상승(5계단↑) / 상승 / 유지 / 하락
3. **근거 수집** (`evidence.py`): 네이버 검색 API로 최근 3일 뉴스·블로그
4. **원인 분석** (`analyzer.py`): 근거 안에서만 원인 분류 + 1~2문장 이유. 근거가 없으면 LLM 호출 없이 "원인 불명확"
5. **인사이트** (`analyzer.py`): 연령대별 핵심 인사이트 3개
6. **리포트** (`report.py`): `reports/날짜.html`(연령 탭) + `reports/날짜.json`(다른 시스템 연동용)

## 이 도구로 알 수 있는 것과 없는 것

- 알 수 있는 것: 네이버 쇼핑에서 **여성 연령대별로 무엇을 많이 검색했는지**, 순위가 어떻게 움직이는지, 같은 시기 어떤 기사·글이 나왔는지
- 알 수 없는 것: 실제 판매량, 올리브영 등 다른 채널 순위, 인스타그램·틱톡 화제성, 검색량의 절대 크기
- "왜 떴는지"는 근거 글을 바탕으로 한 **추정**이에요. 광고·체험단 표시가 있는 블로그 글은 근거에서 빼고, 뉴스를 블로그보다 무겁게 봐요.
  최종 해석은 마케터 노트에 직접 남기는 것을 전제로 설계했어요.

## 설치 후 처음 할 일

```bash
python main.py --test     # 데이터랩 수집, 네이버 검색, 쇼핑 검색이 되는지 점검
python main.py            # 실제 실행
python main.py --check    # 오늘 검색어의 품목·브랜드 분류를 check_날짜.csv 로 저장 (엑셀로 열어 틀린 것 확인)
```
틀린 분류는 `config.py` 의 `CATEGORY_OVERRIDES`, `BRAND_OVERRIDES` 에 적고 `python main.py --rebuild` 하면 바로 반영돼요.

## 네이버 검색 API 키 (선택)

2026년 6월부터 네이버 검색 API는 개발자센터가 아니라 **네이버 클라우드 플랫폼의 NAVER API HUB**에서 새로 발급해요.
가입할 때 결제 카드 등록이 필요하고, 요금은 종량제지만 지금은 한시적 무료로 안내되어 있어요.

키가 없어도 프로그램은 돌아가요(**키 없이 쓰기 모드**).

| 기능 | 키 없이 | HUB 키 | 예전 개발자센터 키 |
|---|---|---|---|
| 연령별 순위·품목·주간 흐름·검색·노트 | ✅ | ✅ | ✅ |
| 브랜드 묶기 | ✅ 추정 규칙 + 별칭 | ✅ 추정 규칙 + 별칭 | ✅ 쇼핑 검색으로 판별 |
| "왜 떴는지" 근거(뉴스·블로그) | ❌ 노트로 직접 | ✅ | ✅ |
| 팝업·행사 자동 수집 | ❌ | ✅ | ✅ |

HUB 키를 받으면 `.env` 에 `NAVER_API_MODE=hub` 와 Client ID / Secret 을 넣으세요.
유료 전환이 걱정되면 HUB 콘솔의 [한도 및 알림]에서 API별 상한을 걸어 두세요.

## 비용: 전부 무료로 쓸 수 있어요

기본값은 **무료 모드**(`ANALYZER=free`)입니다. 필요한 건 네이버 검색 API 키뿐이에요.

| 항목 | 무료 모드 | 비용 |
|---|---|---|
| 인기검색어 순위 수집 (네이버 데이터랩) | 키 필요 없음 | 무료 |
| 근거 기사·블로그 검색 (네이버 검색 API) | 선택. NAVER API HUB 키 | 현재 한시적 무료 (카드 등록 필요) |
| 원인 분류·인사이트·행사 정리 | 규칙 기반 (`rules.py`) | 무료 |
| 매일 자동 실행 | 내 컴퓨터, 또는 GitHub Actions | 무료 |
| 홈페이지 공개 | GitHub Pages (공개 저장소) | 무료 |

무료 모드는 AI 대신 기사·글에 자주 나온 단어로 이유를 분류하고, 순위 변동을 계산해 인사이트를 만듭니다.
문장이 AI보다 단순하지만 근거(출처)가 함께 보여서 확인하기 쉬워요.
나중에 더 자연스러운 분석을 원하면 `.env` 에서 `ANALYZER=claude` 로 바꾸고 Claude API 키를 넣으면 됩니다(유료).

## 시작하기

```bash
pip install -r requirements.txt          # Claude 분석까지 쓰려면 requirements-claude.txt 도 설치
cp .env.example .env        # 네이버 검색 API 키 2개 입력
python main.py --demo       # 키 없이 화면부터 확인
python main.py              # 실제 실행 (기본: 어제 날짜)
```

## 포트폴리오로 쓰기

1. 매일 실행해서 기록을 쌓고, 브리핑을 보며 노트에 한두 줄씩 해석을 남기세요.
2. 일주일에 한 번 노트를 `notes.md` 에 옮기고 실행하면 홈페이지 '마케터 노트 모아보기'에 공개돼요.
3. 포트폴리오에는 문제 → 방법(데이터 수집, 원인 분류, 무료 구축) → 결과 화면 → 내가 발견한 인사이트 순서로 정리하세요.
4. 공개할 때는 "네이버 데이터랩 기반 비상업적 개인 프로젝트"라고 출처를 밝혀 두세요.

## 순위는 몇 위까지 모으나요?

연령대마다 **1~100위**(`COLLECT_N`)를 모읍니다. 이유 분석과 순위표는 1~50위(`TOP_N`), 검색·품목·브랜드·주간 흐름은 100위까지 써요.
데이터랩 요청이 연령당 5번이라 부담이 적고, 요청 사이에 1.5초씩 쉬어요.

## 지원 브랜드 설정 (현재: 메디큐브)

`config.py` 에서
- `WATCH_BRANDS`: 관심 브랜드. 맨 앞이 지원 브랜드(메디큐브), 나머지는 비교 브랜드(달바, 톰, 리쥬란). 카드가 나란히 보여요.
- `BRAND_ALIASES`: 브랜드 이름 없이 검색되는 대표 제품명(예: 에이지알, 부스터 프로, 제로모공패드). 이 말이 들어간 검색어는 모두 메디큐브로 묶여요. 신제품이 나오면 여기에 추가하세요.

관심 브랜드 카드에는 그 브랜드 검색어의 품목 구성(예: 스킨케어 5 · 뷰티디바이스 2)이 함께 나와서,
화장품과 디바이스 중 어느 쪽 관심이 큰지 볼 수 있어요.

## 관심 브랜드 바꾸기

- **홈페이지에서 바로:** 브랜드 이름을 넣고 [추가], 카드의 ✕로 빼기, ☆로 지원 브랜드 표시. 이 브라우저에만 저장돼요.
- **기본 목록과 매일 관심도 수집 대상:** `watch_brands.txt` 를 고쳐요(한 줄에 하나, 맨 위가 지원 브랜드).
  GitHub에서는 파일을 열고 연필(✏️) → 수정 → Commit changes. 다음 자동 실행부터 반영돼요.
  관심도 비교는 네이버 API 제한으로 한 번에 최대 5개예요.

## 브랜드 검색

검색창에 브랜드 이름(예: 메디큐브)을 넣으면 그 브랜드의 상품 검색어가 모두 모여 나옵니다.
'메디큐브 마스크팩'처럼 이름이 들어간 검색어는 물론, '에이지알 부스터프로'처럼 브랜드 이름이 없는 상품 검색어도 묶여요.

`brands.py` 가 매일 새로 나타난 검색어마다 네이버 쇼핑 검색 API(무료, 같은 키)로 상품을 확인해서,
화장품/미용 상품의 절반 이상이 한 브랜드면 그 브랜드로 정합니다. '선크림'처럼 여러 브랜드가 섞인 일반 검색어는 브랜드 없음으로 둬요.
한 번 판별한 검색어는 DB에 저장되므로 첫날에만 호출이 많고(약 300~400번), 이후에는 새 검색어만 확인합니다.
네이버 검색 API의 하루 무료 한도 안에서 충분히 돌아가요.

순위는 데이터랩 인기검색어 100위 안에 든 검색어만 알 수 있어요. 100위 밖 상품은 순위 대신
결과 화면의 "네이버 쇼핑에서 상품 보기" 링크로 확인하세요.

## 팝업·행사 수집

매일 실행할 때 `config.py` 의 `EVENT_QUERIES`(예: 뷰티 팝업스토어, 성수 뷰티 팝업, 더현대 뷰티 팝업)로 최근 7일 뉴스·블로그를 찾고,
AI가 글에 날짜와 장소가 적힌 뷰티 행사만 골라 DB에 쌓습니다. 글에 없는 날짜나 장소는 만들어 내지 않도록 지시했지만,
블로그 글은 틀릴 수 있으니 방문 전 공식 안내를 확인하세요. 검색어를 추가하면 다른 지역이나 행사 유형도 넓게 잡을 수 있어요.

## 타깃 성별

지금은 **여성** 검색만 수집하고 분석합니다. `config.py` 의 `GENDER` 를 `"m"`(남성) 또는 `""`(전체)로 바꾸면 타깃이 바뀌고, 성별마다 DB 파일이 따로 생겨 데이터가 섞이지 않습니다.

## 홈페이지

실행할 때마다 `site/index.html` 이 새로 만들어집니다. 파일을 더블클릭하면 바로 열리고, 그대로 웹에 올려도 됩니다.

- 첫 화면: 연령대별 1위 키워드 스와치, 날짜 선택(‹ › 버튼이나 목록), 키워드·브랜드 검색창
- 3줄 브리핑: 그날 가장 크게 오른 키워드와 이유, 가장 많이 검색된 브랜드와 어제보다 뜬 브랜드, 연령별로 많이 찾은 품목
- 마케터 노트: 브리핑 옆 칸에 그날의 해석을 적으면 브라우저에 저장. '노트 파일용으로 복사'로 notes.md 에 옮기면 홈페이지에 공개 노트로 실림
- 연령별 인기 품목: 상위 100개 검색어를 선케어·립·스킨케어 등으로 나눈 막대. 칸을 누르면 그 품목 검색어 목록. 분류 사전은 config.py 의 PRODUCT_CATEGORIES
- 브랜드 랭킹: 전체/연령별로 100위 안 상품 검색어가 많은 브랜드, 최고 순위, 어제 대비 증감
- 관심 브랜드: `config.py` 의 `WATCH_BRANDS` 에 적거나 홈페이지에서 추가한 브랜드를 카드로 매일 추적 (연령별 최고 순위, 최근 14일 그래프, 일주일 전 대비)
- 이번 주 흐름: 이번 주 7일과 지난주 7일의 평균 순위를 비교해 꾸준히 오른 / 새로 자리 잡은 / 주춤한 키워드 (하루짜리 반짝 변동은 걸러짐)
- 덜 중요한 섹션(세대 공통 키워드, 지난 기록)은 접어 두고 필요할 때 펼치기
- 연령별 순위: 인사이트, 원인 분포, 1~50위와 이유, 새로 뜬 키워드만 보기, 키워드 찾기
- 급상승: 전 연령에서 가장 크게 오른 키워드
- 뷰티 팝업·행사: 보고 있는 날짜 기준으로 진행 중이거나 3주 안에 여는 팝업을 입장권 모양 카드로 보여줌 (오늘 마감, D-n, 남은 날, 지역·예약 방법, 출처). 브랜드가 검색 순위에 있으면 함께 표시
- 세대 공통 키워드
- 키워드 검색: 맨 위 검색창에 키워드(예: 틴트)를 넣으면 연령대별 현재 순위(100위까지)와 전날 대비 변동, 그 단어가 들어간 다른 검색어(립틴트, 틴트 추천 등), 최근 30일 순위 그래프를 보여줌. 기간 내내 순위권이면 스테디 키워드로 표시
- 지난 기록: 날짜를 누르면 그날로 이동

홈페이지에는 최근 30일(`config.py` 의 `SITE_DAYS`)이 담기고, 그보다 오래된 날짜는 아래 날짜별 리포트로 남습니다.
디자인을 바꾸려면 `site_template.html` 을 고친 뒤 `python main.py --rebuild` 를 실행하세요.

## 날짜별로 쌓고 다시 보기

실행할 때마다 결과가 지워지지 않고 계속 쌓입니다.

- `beauty_trend.db`: 모든 날짜의 순위, 원인 분석, 인사이트 누적 저장소
- `reports/index.html`: **날짜 목록. 여기서 시작하세요.** 날짜별로 연령대 1위 키워드가 색 막대로 보입니다.
- `reports/YYYY-MM-DD.html`: 그날의 리포트. 상단 버튼이나 키보드 ←/→ 로 전날·다음날로 이동합니다.
- `reports/YYYY-MM-DD.json`: 그날의 원본 데이터 (엑셀이나 다른 도구로 옮길 때)

```bash
python main.py --date 2026-11-10                    # 특정 날짜 하나
python main.py --from 2026-11-01 --to 2026-11-10    # 지난 기간 한꺼번에 채우기
python main.py --rebuild                            # 디자인을 바꾼 뒤 모든 날짜 리포트 다시 그리기 (API 비용 없음)
```

지난 기간을 채울 때 순위는 정확히 가져오지만, 근거 검색이 최신 글 위주라 오래된 날짜일수록 "원인 불명확"이 많아집니다.

## 매일 자동 실행

데이터랩의 일간 데이터는 보통 하루 늦게 반영되므로, 매일 아침 "어제" 날짜를 분석하도록 되어 있습니다.

**방법 1. 내 컴퓨터에서 (컴퓨터가 켜져 있어야 함)**

- 윈도우: 작업 스케줄러 > 기본 작업 만들기 > 매일 오전 9시 > 프로그램 시작에 `run_daily.bat` 지정
- 맥/리눅스: `crontab -e` 에 아래 한 줄 추가
  ```
  0 9 * * * /경로/beauty_trend/run_daily.sh
  ```

**방법 2. GitHub Actions (컴퓨터를 꺼 둬도 됨, 휴대폰으로 확인 가능)**

1. 이 폴더를 GitHub 저장소로 올립니다. (`.env` 는 올리지 마세요)
2. Settings > Secrets and variables > Actions 에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` 를 등록합니다.
3. Settings > Pages > Source 를 "GitHub Actions" 로 바꿉니다.
4. Actions 탭에서 `daily-beauty-trend` 를 한 번 수동 실행해 동작을 확인합니다.

이후 매일 아침 자동으로 분석하고, DB와 리포트를 저장소에 쌓은 뒤 `https://아이디.github.io/저장소이름/` 에 홈페이지를 올립니다. 전체 기간 날짜별 리포트는 같은 주소 뒤에 `/reports/` 를 붙이면 볼 수 있어요.
무료로 쓰려면 공개(Public) 저장소여야 Pages가 열리고, 그러면 홈페이지를 누구나 볼 수 있어요. 공개가 곤란하면 방법 1(내 컴퓨터)로 돌리고 `site/index.html` 을 직접 열어 보세요. 또 네이버가 해외 클라우드 서버의 접속을 막으면 수집이 실패할 수 있는데, 그때는 방법 1을 쓰세요.

## 비용 줄이는 설계

- 같은 키워드는 여러 연령대에 나와도 **하루 1번만** 분석합니다.
- 신규·급상승이 아닌 키워드는 **최근 7일 안의 분석을 재사용**합니다. (첫 실행 날만 전체 분석)
- 근거가 없는 키워드는 LLM을 부르지 않습니다.
- `.env`의 `ANTHROPIC_MODEL`을 더 가벼운 모델로 바꾸면 비용이 더 내려갑니다.

## 꼭 알아둘 점

- 인기검색어 순위는 공식 오픈 API가 아니라 데이터랩 웹 화면이 쓰는 내부 주소에서 가져옵니다.
  네이버가 주소를 바꾸면 `collector.py`의 `URL`과 파라미터를 개발자도구(Network 탭)로 확인해 고쳐야 하고,
  상업적 사용 전에는 네이버 이용약관을 확인하세요.
- 데이터랩 수치는 상대값입니다. 실제 검색량이 필요하면 네이버 검색광고 키워드도구를 함께 쓰세요.
- 연령 구분은 네이버 로그인 사용자 기준입니다.
- 조정할 값(순위 수, 급상승 기준, 재사용 기간, 원인 분류 목록)은 모두 `config.py`에 있습니다.
